El pipeline que alerta pero no bloquea

pipeline-tipico.yml

name: security
jobs:
  sast:    # corre Semgrep…
    continue-on-error: true    # …y sigue aunque falle
  deps:    continue-on-error: true
  container:  continue-on-error: true

Doce escáneres, un montón de anotaciones rojas en la pestaña Actions, y main sigue en verde con las vulnerabilidades adentro. El equipo se acostumbra al ruido y deja de mirarlo.

Un reporte que no bloquea no es un control: es una métrica de culpa.

Preguntar a la clase: ¿en sus empresas el pipeline de seguridad falla el build o solo comenta? La respuesta casi siempre es «solo comenta». Ese es el patrón que vamos a romper hoy.
